# BobFull 담당자 AI PR 검토·리뷰 반영 가이드

## 1. 역할

이 문서는 PR 담당자의 AI가 자신의 연결 PR을 최신 Head 기준으로 다시 검토하고, PR Conversation에 AI Review 결과를 남기며, Human 이해도와 Human 리뷰를 처리할 때 사용하는 기준이다.

**모든 PR은 담당자 AI Review가 필수**다. 문서·설정·단순 CRUD라고 해서 생략하지 않는다. 다만 리뷰 흔적을 만들기 위해 의미 없는 지적을 억지로 생성하지 않는다.

다른 팀원 AI 또는 외부 AI 리뷰는 추가 입력이며 필수 Gate가 아니다. PR에 리뷰·댓글이 등록되면 작성 주체와 관계없이 실제 코드·계약·테스트 근거로 판단한다.

담당자 AI는 Approve와 Merge를 수행하지 않으며 Human 코드 리뷰를 대체하지 않는다.

## 2. 실행과 시작 조건

연결된 PR의 검토·리뷰 반영에는 다음 명령을 사용한다.

```text
PR #번호 검토하라
```

Draft PR 생성 직후에도 별도 명령을 기다리지 않고 `skills/bobfull-pr-review/SKILL.md`를 적용해 최소 1회의 AI Review 댓글을 남긴다.

담당자 AI는 PR 번호로 연결된 모든 Issue, 각 Issue 댓글의 최종 계약, 현재 `status:*` Label과 PR 상태를 읽고 PR 검토·리뷰 반영 단계부터 재개한다. 실제 상태는 GitHub `status:*` Label 하나로만 관리한다.

### 최소 검토 조건

다음 세 가지를 확인할 수 있으면 현재 상태와 관계없이 검토한다.

1. 최신 Head Commit SHA
2. 최신 Head의 실제 Diff
3. 해당 PR의 연결된 Issue 또는 작업 범위

Draft 상태, 테스트 실패·미실행, `FAIL`·`HOLD`·`NOT_RUN`, Human 입력 미작성, 외부 리뷰 부재, PR 설명 불일치는 검토 중단 사유가 아니다. 현재 결함·확인 필요·미검증 위험으로 기록한다.

## 3. 검토 입력

가능한 범위에서 다음을 확인한다.

- 연결된 모든 Issue의 최종 계약과 현재 `status:*` Label
- 최종 계약 이후 변경 여부
- PR 본문과 최신 실제 Diff
- `skills/bobfull-pr-explain/SKILL.md`
- `skills/bobfull-pr-review/SKILL.md`
- 관련 코드와 테스트
- 테스트·build·직접 검증·CI 증거
- 미검증 범위와 남은 위험
- 강화 검토 PR의 담당자 Human 이해도 답변
- Human 리뷰 의견
- 기존 AI Review·Review·Conversation 댓글·inline comment

리뷰·댓글의 작성자가 Human인지 AI인지에 따라 우선순위를 자동으로 정하지 않는다. 실제 근거로 판단한다.

## 4. 코드와 계약 검토

### 기본 검토

모든 PR에서 다음을 확인한다.

- 연결 Issue의 범위·제외 범위·완료 조건
- Issue 최종 계약과 실제 Diff의 일치
- 요청부터 응답·저장까지 실제 코드 흐름 또는 문서 변경 흐름
- 입력 검증과 예외 처리
- 코드와 PR 이해 요약의 일치
- 의미 있는 실행 흐름이 있는 기능 PR의 Mermaid 최신 Head 일치 여부
- 테스트와 완료 조건의 연결
- 실제 실행 결과와 미검증 범위
- 범위 밖 변경과 불필요한 복잡성
- 비밀정보·개인정보 포함 여부

단순 문서·설정·CRUD PR에서도 이 검토를 수행하되, 해당하지 않는 고급 항목을 억지로 지적하지 않는다.

### 강화 검토

인증·결제·환불·예약·좌석·상태 변경·정산·외부 연동·동시성·이벤트·캐시·인프라 핵심 변경 등 실패 비용이 큰 PR에는 다음을 추가한다.

- 구현 전 설계 확인 수행 여부
- 책임 클래스·상태 변경 위치·트랜잭션 범위·실패 처리 방식과 최신 Diff 일치 여부
- 인증·인가·소유권
- 트랜잭션·Rollback·부분 성공
- 상태·금액·수량 정합성
- 중복 요청·멱등성
- 동시성·락·재시도
- Event 경계·AFTER_COMMIT·Outbox 등 후속 처리 경계
- 외부 연동 실패와 보상

강화 검토의 구현 전 설계 확인 기록은 PR Conversation 댓글에 남기며 Issue 댓글이나 PR 본문에 중복하지 않는다.

## 5. 담당자 AI Review

### 5.1 필수 실행 시점

모든 PR에서 `skills/bobfull-pr-review/SKILL.md`를 적용한다.

- Draft PR 생성 직후
- `PR #번호 검토하라`
- BLOCKER/MAJOR 수정 후
- 새 Commit으로 Head가 바뀐 뒤
- Ready 전환 또는 Human 최종 리뷰 요청 전

이전 Head의 PASS를 최신 Head의 PASS로 재사용하지 않는다.

### 5.2 중요도 기준

- **BLOCKER**: Merge하면 안 되는 보안·데이터·정합성·핵심 계약 훼손 문제
- **MAJOR**: 요구사항 실패·주요 런타임 오류·필수 실패 처리 누락·핵심 설계 문제
- **MINOR**: Merge를 직접 막지는 않지만 유지보수성·명확성·테스트 정확도를 위해 수정 가치가 있는 문제
- **SUGGESTION**: 현재 구현도 허용 가능하며 선택적으로 개선할 수 있는 제안
- **PASS**: 실제 근거를 다시 확인했고 보고할 BLOCKER·MAJOR·MINOR가 없음

근거 없는 추측, 개인 취향, Issue 밖 미래 기능을 이유로 지적하지 않는다.

### 5.3 PR Conversation 댓글

각 정식 AI Review 실행은 PR Conversation 댓글을 남긴다.

```markdown
## 담당자 AI Review

- 기준 Head: `<SHA>`
- 연결 Issue: `#번호`
- 검토 수준: `기본 | 강화`

### BLOCKER
- 없음 또는 실제 지적

### MAJOR
- 없음 또는 실제 지적

### MINOR
- 없음 또는 실제 지적

### SUGGESTION
- 없음 또는 실제 제안

### 판정
`PASS | 수정 후 재검토 필요`

### 검증 근거
- 확인한 테스트·build·직접 검증·CI와 남은 NOT_RUN
```

실제 지적은 반드시 `BLOCKER → MAJOR → MINOR → SUGGESTION` 순서로 배치한다. BLOCKER 또는 MAJOR가 있으면 `수정 후 재검토 필요`로 기록하고 수정 뒤 최신 Head에서 다시 Review한다.

## 6. Human 이해도 정책

Issue 단계와 PR 단계를 구분한다. 이번 PR 병목 완화 정책은 **PR 단계 질문 수만 변경**하며 Issue 단계의 구현 착수 질문 정책은 유지한다.

### 6.1 Issue 단계

Issue 단계 Human 질문은 구현 전에 정책·범위·흐름을 담당자가 이해하고 결정해야 하는지를 확인하기 위한 것이다.

- 기본 검토: 필요한 질문만 1~2개
- 강화 검토: 필요한 질문만 2~3개
- 특정 클래스·메서드 암기나 프레임워크 내부 구현 퀴즈를 만들지 않는다.
- 코드 탐색 없이 신입 백엔드 기본 개념과 현재 Issue의 정책·흐름을 설명할 수 있는 수준으로 작성한다.
- Human 결정이 필요하지 않은 내용은 억지 질문으로 만들지 않는다.

담당자 Human은 Issue 본문의 1차 답변과 최종 확인을 직접 작성하고, 담당자 AI는 실제 계약·코드·문서를 근거로 답변을 대조한다.

### 6.2 PR 단계 — 기본 검토

```text
Human 이해도 질문: 0개
```

문서·설정·단순 CRUD·기존 패턴 반복처럼 별도 학습 검증 가치가 낮은 PR에서 질문을 만들지 않는다. PR 본문에는 `해당 없음: 기본 검토`로 기록한다.

### 6.3 PR 단계 — 강화 검토

```text
Human 이해도 질문: 정확히 3개
```

세 축을 고정한다.

1. **핵심 실행 흐름**: 이 PR이 실제로 어떤 순서와 주요 분기로 동작하는가
2. **중요 기술 개념**: 가장 중요한 개념이 무엇이고 어디에 왜 적용됐는가
3. **설계 판단과 한계**: 왜 이 방식을 선택했고 주요 실패 처리와 남은 한계가 무엇인가

질문 문장은 현재 PR에 맞게 구체화하되 세 축을 늘리거나 줄이지 않는다. 특정 클래스·메서드 암기, 프레임워크 내부 구현 퀴즈, 코드 탐색 문제로 만들지 않는다.

담당자 AI는 각 1차 답변을 최신 코드와 비교해 `AI 답변 검토: 일치 | 보완 필요 | 미작성`과 `AI 기준 답변`을 작성한다. Human 답변 원문과 최종 확인을 수정하거나 대신 작성하지 않는다.

기본 검토 PR에는 Human 이해도 답변이 Merge 조건이 아니다. 강화 검토 PR은 Merge 전 3문항 답변과 AI 대조가 필요하다.

## 7. Human Review Checklist와 댓글 확인

Human Review Checklist는 PR마다 임의의 세부 구현 질문을 동적으로 생성하지 않는다. 모든 PR에서 다음 공통 이해 확인을 사용한다.

- [ ] 이 PR이 무엇을 왜 변경하는지 이해했다.
- [ ] 변경 후 기본 실행 흐름과 중요한 분기를 이해했다.
- [ ] 이 PR에 중요한 기술 개념이 있다면 어디에 왜 적용됐는지 이해했다.
- [ ] 테스트·검증 결과와 남아 있는 미검증 위험을 확인했다.

Human 리뷰어는 PR 본문을 수정하지 않고 체크리스트를 참고해 PR 댓글에 체크 여부와 의견을 직접 작성한다.

담당자 AI는 댓글의 체크 여부와 의견을 작성하거나 수정하지 않는다. 최신 Diff를 기준으로 추가 설명 요청과 문제 제기를 대조해 실제 결함·테스트 공백·계약 충돌인지 판단한다.

## 8. 리뷰·댓글 판단

담당자 AI Review 댓글은 필수 기록이다. 그 외 리뷰·댓글은 추가 입력이다.

### 명확한 결함

- 실제 코드·Issue 계약·테스트 근거가 있음
- Issue 범위 안에서 수정 가능함
- 정책 재결정이 필요하지 않음

처리:

- 실제 파일 수정 시작 전 연결 Issue를 `status:in-progress`로 전환
- 수정
- 영향받는 테스트·build·직접 검증 재실행
- PR 기록 갱신
- 최신 Head에서 AI Review 재실행과 새 댓글 작성

### 설명 또는 확인 요청

- 확인 결과와 코드 근거 기록
- 임의 코드 수정하지 않음

### Human 결정 필요

- 정책·API·DB·상태·권한·트랜잭션 재결정
- 다른 담당자 계약 변경
- 범위 확장 또는 새로운 기술 도입

처리:

- 수정하지 않음
- Human 결정 요청

### 미반영

- 근거를 확인할 수 없음
- Issue 범위 밖임
- 이미 해결됐거나 현재 Head에 적용되지 않음

처리:

- 반영하지 않은 이유 기록

## 9. 담당자 AI 검토 결과 기록

PR 본문의 `담당자 AI 검토·수정 기록`에는 실제 Review 댓글을 장문으로 복사하지 않고 최신 상태를 요약한다.

```markdown
### 담당자 AI 검토·수정 기록

- 담당자 AI 검토 기준 Head:
- 담당자 AI 검토 결과: `PASS | 수정 후 재검토 필요 | 확인 필요`
- 최신 AI Review 댓글:
- 확인한 기존 PR 리뷰·댓글:
- 반영한 항목:
- 반영하지 않은 항목과 이유:
- Human 결정이 필요한 항목:
- 재실행 테스트·build 결과:
- 최신 Head SHA:
- 남은 미검증 위험:
```

`PASS`여도 확인 범위와 미검증 위험을 기록한다. 이 결과는 Human Approve나 Merge 가능 판정이 아니다.

## 10. 최신 Head 재검토

수정 Commit이 올라오면 이전 결과를 그대로 재사용하지 않는다.

- 현재 Head SHA와 수정 Diff 확인
- 기존 지적 해결 여부 확인
- 영향받은 테스트·build·직접 검증·CI 확인
- 새 결함과 PR 이해 요약·상세 검증 불일치 확인
- 강화 검토일 때 Human 3문항 답변과 AI 기준 답변 재대조
- PR 댓글의 Human 리뷰 의견과 최신 Diff 대조
- 남은 리뷰·댓글 확인
- `bobfull-pr-review` 재실행
- 최신 Head 기준 새 AI Review 댓글 작성

## 11. Merge 전 경계

다음이 충족돼야 담당자 AI가 연결된 Issue에 `status:final-human-review`를 적용하고 Human 최종 리뷰를 요청할 수 있다.

- 모든 PR에서 최신 Head 기준 담당자 AI Review 완료
- 해결되지 않은 BLOCKER 없음
- 필수 테스트·build·직접 검증 결과 확인
- 강화 검토 PR이면 Human 이해도 3문항과 AI 대조 완료
- 기본 검토 PR이면 Human 이해도 질문 없음
- 남은 Human 결정 필요 사항 명시
- 기존 최종 계약 안에서 수정 가능한 미해결 항목은 수정·재검증 완료

`status:final-human-review`는 Human 리뷰를 기다리는 상태다. GitHub Rules의 Human 리뷰·Approve 조건과 Merge 결정은 Human이 담당한다.

## 12. 금지 사항

담당자 AI는 다음을 수행하지 않는다.

- Human 답변 또는 Human 리뷰 대리 작성
- Human Review Checklist 선체크
- 근거 없는 리뷰 의견 생성 또는 자동 반영
- 정책·API·DB·권한·트랜잭션 임의 결정
- 이전 Head PASS를 최신 Head에 재사용
- Approve
- Merge
